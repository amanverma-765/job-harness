# Cold Email Writer & Hiring-Gap Outreach

## When to Use This Skill
- Whenever drafting cold outreach to engineering managers, founders, or team leads.
- For packaging a verified technical hiring gap into a cold email and 1-weekend MVP demo.

---

## The Core Philosophy
Cold emails fail when they sound like cover letters, sales pitches, or generic flattery. The email must read like an engineer writing to another engineer about an interesting architectural problem, unaddressed bug, or performance bottleneck.

---

## Strict Rules & Constraints

1. **Length & Budget:**
   - For hiring-gap pitch: **strictly <= 120 words total** in the body.
   - For standard introduction: 150–200 words max.
   - Zero resume attachment on the first email.

2. **Subject Line:**
   - **Strictly <= 7 words.**
   - References the specific technical gap or observation (e.g. `Fixing API rate limits on worker nodes` or `Reducing hybrid retrieval latency on CPU`).
   - Never use clickbait, "Job inquiry", or "Application for X".

3. **Email Structure (4-Part Architecture):**
   - **Line 1 (The Hook):** Cites specific evidence from recent engineering blogs, open GitHub issues, or changelogs.
   - **Line 2 (The Solution):** Explains what was built/tested to solve this specific problem and the quantitative outcome.
   - **Line 3 (The Proof):** Direct link to a public GitHub repo or deployed demo.
   - **Line 4 (The Soft Ask):** Low-pressure closing question: *"Worth 15 minutes to chat through the trade-offs?"*

4. **Follow-up Email (Day 5):**
   - Strictly 2 lines bumping the thread with a fresh insight or benchmark.

5. **1-Weekend MVP Specification:**
   - Accompanies the email in `outreach.md`:
     - Scope: One-paragraph description (what it builds, what it skips).
     - Stack: Matches target company stack.
     - Deliverable: Deployed demo URL + public repo with clean README + 60-second video walkthrough.
